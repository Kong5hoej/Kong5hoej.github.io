# Kong5hoej.github.io

My personal portfolio and CV, live at **https://kong5hoej.github.io**.

Plain HTML, CSS and JavaScript. There are no dependencies and no build step.

## Pages

| Page | File | What's on it |
| --- | --- | --- |
| Home | `index.html` | The intro screen: name, the quick facts in a code editor window, role, tagline, quick links and the *Play my portfolio* button (under the name on wide screens, under the links on narrow ones). Sized to fit one screen on computers and tablets; on phones it may scroll a little. |
| Projects | `projects.html` | The project list. |
| Experience | `experience.html` | About text, a timeline of work, education and activities, spoken languages and a link to the Toolbox. |
| Toolbox | `toolbox.html` | The tech stack: a card per skill showing where it was used (work, projects, study), worked out from the rest of `content.js`. Tools from an ongoing job are marked "In use now". |
| Contact | `contact.html` | Email, phone and links, with copy buttons. |
| CV | `cv.html` | The printable CV. |
| Pixel Town | `play.html` | The portfolio as a little top-down pixel-art game, opened from the home page. See below. |

GitHub Pages also serves these without the extension (e.g. `/projects`).

## Editing content

All text on the site lives in **[`assets/js/content.js`](assets/js/content.js)**: name, contact details, links, projects, skills, the CV and the page titles. Lines marked `TODO` still hold placeholder text.

- **Relevant vs. all experience:** every CV entry has `relevant: true | false`. The Experience page and the CV open in the *Relevant* view. Visitors can switch to *All experience*, or you can link straight to it with `?view=all` (e.g. `cv.html?view=all`).
- **Dates:** use `"YYYY-MM"` or `"YYYY"`, and `end: null` for "Present". Entries are sorted newest first automatically.
- **Emphasis:** in the tagline, about text and page titles, wrap words in `*asterisks*` to set them in the italic gradient font.
- **Photo:** drop an image in `assets/img/` and set `person.photo`. Your initials are shown when it's empty.
- **PDF:** the *Save as PDF* button on the CV uses a print stylesheet tuned for A4. It always prints in the light theme and only includes the entries currently shown.

The header, phone menu and footer are generated by `main.js`, so a new nav link only needs adding to the `NAV` list there. Each page's `<title>` and description meta tags are in its own `<head>`, so search engines see them without running JavaScript.

## Effects

[`assets/js/fx.js`](assets/js/fx.js) adds the decorative layer. It's independent of the content, so the site works without it.

- **Starfield background:** drifting, twinkling stars at different depths, drawn on a canvas. Stars part around the cursor and link up into constellation lines, a click sends out a pulse, and now and then a shooting star crosses the sky. Tune it with the constants at the top of `createSky()`. Its colours come from the `--star-*` tokens in `style.css`.
- **Custom cursor:** a dot plus a trailing ring that grows over links and buttons. Add `data-cursor="Label"` to any element to show a label in the ring.
- **Reactive name:** the hero name uses a variable font, and letters thin out as the cursor passes.
- **Intro:** on a fresh visit or a reload, the stars come out one by one before the page content appears. Moving between your own pages skips it. The timing is the `--intro` variable in `style.css`.
- **Code editor:** the front page shows `facts` from `content.js` as a TypeScript file in a VS Code-style window, in VS Code's light or dark colours to match the theme. On a fresh visit the code is typed in, and clicking in the code moves the caret, with the line and column in the status bar. The other tabs are links: `package.json` (with the pulsing dot) opens the Toolbox, and the others open the Projects and CV pages. The window sits beside the name with the role and tagline under it. On phones and windows narrower than 1000px, everything stacks under the name, centred. The whole window grows with the screen. This lives in `main.js` (`renderEditor` and `setupEditor`), not `fx.js`.

The navigation (in `main.js` and the "dock" styles) sits in the middle of the header as a small rocket. Hovering it slides the links out to the right (in the order of the `NAV` list), and clicking the rocket goes home. On touch screens and windows narrower than 1200px, the rocket opens a full-screen menu instead. (Below that the open dock would cover the theme toggle; adding a nav link makes it wider, so check that width again.)

Every page draws the same sky and continues it where the last page left off, and in browsers that support it pages crossfade instead of flashing. On touch devices the cursor effects are skipped. With *reduce motion* turned on in the OS, everything is static.

## Pixel Town

`play.html` turns the portfolio into a small retro town to walk around in. Every building opens a window with content from `content.js`: the house is the About card, the lab holds the projects as cartridges, the office and school share a quest log (relevant entries are main quests, the rest side quests), the shop is the toolbox and the post office is the contact page. People and signs around town mention bits of the CV, and wild bugs live in the tall grass.

- **No game required:** the title screen has a quick menu, `M` opens a map that reaches everything, and `play.html#projects` (or `#about`, `#work`, `#school`, `#skills`, `#contact`, `#map`) opens a section directly.
- **Controls:** arrow keys or WASD to walk, Shift to run, Space to talk and go in, or click/tap where you want to go. Touch screens get a pad and A/B buttons.
- **Day and night** follow the visitor's clock (switchable with `N`). Sound is off until switched on.
- All the art is drawn in code: no image files.

| File | What's in it |
| --- | --- |
| [`assets/js/play-world.js`](assets/js/play-world.js) | The map (as text, one character per tile), the places, your sprite's colours and everything people and signs say. Lines that quote the CV are marked `CV`. |
| [`assets/js/play-art.js`](assets/js/play-art.js) | The palette, sprites and painters for tiles and buildings. |
| [`assets/js/play-game.js`](assets/js/play-game.js) | Movement, dialogue, the windows, battles, sound and drawing. |
| [`assets/css/play.css`](assets/css/play.css) | The title screen, HUD, text box and windows. |

## Running locally

Opening `index.html` directly works. For the closest match to GitHub Pages, serve the folder instead:

```sh
python -m http.server 8000      # or: npx serve .
```

Then open http://localhost:8000.

Check your content before pushing:

```sh
node scripts/validate-content.js
```

## Deployment

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) runs on every push to `main`:

1. **Validate:** syntax-checks the JavaScript and runs `scripts/validate-content.js` (catches typos like a bad date format).
2. **Build:** copies `*.html` and `assets/` into `_site/`.
3. **Deploy:** publishes `_site/` to GitHub Pages.

Pull requests run the validation only and don't deploy.

**One-time setup:** in the repository on GitHub, go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**.
